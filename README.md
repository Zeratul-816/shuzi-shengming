# 数字生命

一个**纯文字、本地记忆**的人格引擎：不是"能答问题的助手"，而是

> 它以自己的视角把发生过的事记成一张张卡片——带时间、带状态（还成不成立）、
> 带关键词、带**它当时注意到的那一部分**。要用的时候先按时间/人物/关键词/情绪把卡片找出来，
> 确认需要细节了，再去翻那一段原始记录。
> 它有一组会渴会累的需求，会自己决定**想不想说话**，也知道自己什么时候该拒绝。
> LLM 只负责把已经定下来的动机说成人话——说完还要过一遍确定性校验。

**v2 的决定是拿掉向量。v3 的决定是把断掉的线接上。** 见「v3 做了什么」。

---

## 一条分寸：机制要准，内容可以错

每个子功能只保证**机制跑顺**：唤醒会记录、名字会绑上、卡片会归档、约束会被检查。
它**不保证内容正确**：名字可能记错，人物可能认混，注意力可能偏，回忆可能串线。

这不是妥协，是取舍——只要"错了能改过来"，错误就是原料而不是负债。
所以判断一道防线该不该加，问的不是"能不能更准"，而是：

| 它防的是什么 | 处置 |
|---|---|
| 机制坏掉（崩溃、无限增长、自指死循环） | 留 |
| 内容不完美（认错了、记偏了、说得不准） | 删，或者改成"可纠正" |

按这条尺子，有些东西被删掉了：名字抽取不再做语义过滤（「我是说」会被认成"说"），
自己的名字也不再是黑名单（他说"我就是你"也照记）。
留下的只有有界性：问身份的额度、卡片判重、提示词预算。

顺带说明一个容易混的地方：v3 的 `verify.ts`（句数／禁语／复述）看起来像在管内容，
其实管的是**机制**——动机卡写了"最多两句"，那个约束有没有真的被执行。
它不判断"这句话说得好不好"，那是 judge 和你的活。

## 30 秒跑起来

需要 Node **≥ 22.6**（原生跑 TypeScript，无需构建）。

```bash
git clone <this-repo> && cd shuzi-shengming
npm install
npm run test       # 106 个测试
npm run eval       # 19 项确定性评测（不花钱）
npm run demo       # 离线跑一遍完整链路
npm start          # 真正的文字对话
```

Windows 可以直接双击 `启动.cmd`：自动装依赖，然后进对话。
想开调试视图（每轮打印意图/情绪/召回通道/合规检查/耗时）就双击 `启动-调试.cmd`。

**仓库里带的是什么人格：** `persona/` 是一份**白模**——占位人设，里面自己写着"架子搭好了，人还没长满"。
改 `identity.md` / `voice.json` 就是做你自己的人设，改完重启（或 `/reseed`）生效。
人设想放在别处（不入库、换着玩），用 `DH_PERSONA_DIR` 指过去：

```bash
DH_PERSONA_DIR=D:\private\persona npm start
```

**仓库里没有的：**

| 没有 | 原因 |
|---|---|
| `data/` | 记忆库跑起来就自己长出来；它含真实对话，不该进版本库 |
| `.env` / key 文件 | 凭证。见下面「接真实模型」 |

## v4 做了什么：人物档案

v3 之前 `person` 表只是个槽位：`name` 硬编码成"你"，`impression` 永远是 NULL，
所有卡片的 `person_id` 都是 1——不是因为它们属于同一个人，而是**没有第二个人可指**。
他第一句就自称「开发者」，那个词只是 entities 里的一个字符串。

**v4 的立场：她看不见对面是谁，所以"不知道"是常态，不是异常。**

| 机制 | 现在怎么工作 |
|---|---|
| **每次唤醒是一个事件** | `awakening` 表记下时间、模式、谁在、有没有问过。醒来时 `identity_known = 0` |
| **谈话对象待定，需要询问** | 第一轮走 `ask_identity` 意图。同一次苏醒只问一次，累计三次他都不说就不再问（`MAX_ASKS`） |
| **预设的待填档案** | 新库的 `person` 是 `dossier_status='unknown'`、`display_name=NULL`。名字要等他自己报 |
| **多别名索引** | `person_alias` 表。「开发者」「你」「老开」是同一个人的三个入口，写入时用来归户，读取时用来称呼 |
| **随聊天归档** | 卡片带 `about` 字段；留空 = 关于他，填名字 = 关于别人。写入时按别名解析成 `person_id` |
| **档案进提示词** | `## 我和他` 分区里写清：我叫他什么、我知道他的哪几条（就是卡片标题，一字不改）、我还不知道什么 |

三条身份通道，各自受控：

1. **同步规则**（回话之前跑）：`我是X` / `叫我X` / `我姓X` / 命中已有别名 / 「是我」。
   必须在调表达层之前完成——否则他刚报完名，她这一轮还在问"你是谁"。
2. **编码器回报**（异步）：长句里的自我介绍由 `Appraisal.speaker` 补，晚一轮生效。
3. **其他人**（`Appraisal.people`）：只有明确提到的**别人**才新建档案。
   **绝不**把 entities 一股脑当人物——里面混着「公司」「报错」，还有她自己的名字（真机上 12 次）。

> **认名字这件事故意不做语义甄别。** 「我是说……」会被抽成"说"，
> 她会真的管他叫一阵子"说"。这不是 bug——误会是人格的原料。
> 要保证的只有两件机制上的事：抽到什么就绑什么；**绑错了能改过来**
> （他再报一次名，`display_name` 覆盖，旧别名留着）。
> 一个从不认错名字的存在不是人，是查表。

真机验收（`npm run eval -- --live`）：

```
你好。
我：……你是谁。                                    ← ask_identity，1 句 6 字
我是开发者。之前来过。
我：开发者……嗯。之前那次我没记住。
...
档案状态 known · 我叫他 开发者 · 别名 开发者 · 关于他 14 张卡
第一次唤醒 asked_identity=1，最后一次 identity_known=1
```

## v3 做了什么

v2 的机制都对，但有大量**写了一半的链路**：算完了、存下了，没人读。v3 只做两件事——把线接上，把承诺变成可执行的检查。
### ① 四条断掉的链路接上了

| v2 | v3 |
|---|---|
| `consolidate` 花钱让模型写 `thread.summary`（来龙去脉），**提示词里从来不渲染** | 卡片骨架里多一行 `≈ 这条线后来的变化`，每条线只渲染一次 |
| 编码器每轮生成 `attention` / `meant_to_me`，**每轮被丢弃** | 落库，并渲染成 `◎ 我当时注意到的是` |
| `card.not_known` 一直是个死字段 | 渲染成 `○ 我当时没懂、也没问` |
| `tension = need^1.6` 算出来传进打分函数，**函数体里一次都没用过** | 真的接上了（换算方式见下） |

### ② 时间驱动的状态过期

v2 里 `status` 只有一个写入者（编码器），于是「他说下周要出差」那张卡在那一周过去之后**仍然是 active**，而且因为 `event_at` 在未来，时间契合度永远满分。现在多了第二个写入者：`memory/status.ts` 的 `refreshStatuses()`，启动和巩固时各跑一次，按 `valid_to` 和「计划的时间已经过去」两条规则自动失效，每次迁移都写 `card_status_log`。

同时修了两个时间语义错误：

- 「最近」通道改成按 **`created_at`（我什么时候得知）**，不再是 `event_at`。否则一张"下周三"的计划卡会永远占着最近三天。
- 未来的卡片不再拿满分时间契合（原来是 `max(0, now - event_at)` 把负距离钳成 0）。现在未来要付 1.5 倍距离代价。

### ③ 回应路径不再是单一意图

v2 的被动回复只有一张卡：`intent=reply`，语气只有"自然/有点省力"两档。也就是说 **95% 的轮次用的是同一张动机卡**，人格差异只发生在主动发言那 5% 里。

v3 加了确定性读句器（`motivation/reader.ts`，纯正则、0 成本）和四个回应型意图：

| 意图 | 触发 | 她要干什么 |
|---|---|---|
| `refuse_care` | 他在关心她 | 否认"我在勉强"。短、硬，但别冷冰冰 |
| `deflect` | 他在问她的感受 | 把话头挪到事实上，或挪到他身上 |
| `test_self` | 他在夸她/催她 | 把注意力从自己身上挪到事情上 |
| `reply` | 默认 | 接住内容 |

连续两轮用同一种接法会打 0.55 折——拒绝被关心不该是个开关。

### ④ 硬约束真的会被执行

提示词里写了 `max_sentences`、`banned_phrases`、`must_not`，v2 里它们全是**文本**。现在 `express/verify.ts` 会查四件事：句数、禁语（逐字扫）、是否复述他刚说的话（bigram Dice ≥ 0.6）、`must_include` 在不在。违规就带着清单重说一次，结果记进 `express_audit`。

> 语义类的禁忌（"不许承认自己在勉强"）**仍然只能靠模型自觉**。这个区别很重要：能查的没查是失职，查不了的没查是边界。

### ⑤ 别的

- **因果链**：编码时让模型指着已有卡片的 `#id` 说"因为那张，所以这张"，写进 `card_link`。串线从此先采信声明，关键词撞车只用来补漏。
- **反刍通道**：12% 概率塞进一张跟话题无关但当时重要的旧卡（"我突然想起"）。这是让记忆像自己有思绪的最便宜手段。
- **情绪同频召回**：心情差时更容易想起难过的卡。`card.valence/arousal` 从 v2 起就在库里，一直没人读。
- **表情滞后**：对外情绪对内在情绪做一阶平滑。她说"没问题"的时候，脸上的东西还没散。
- **人格素体重写**：`persona/` 从"关于架构的说明"改成特质+触发+反方向表现。
- **两种沉默**：`not_now`（不想说，扣联结）和 `declining`（听见了但不接，不扣）。
- **人格的最后一个漏洞**：她以前会对着不存在的记忆说"我记得"。现在规则和提示词都堵住了（真机 judge 的记忆忠实度 6.0 → 9.0）。

## 为什么不用向量

不是省事，是**向量会记错**。

余弦相似度没有时间轴，也没有"是否仍然成立"的概念。三个具体病灶：

| 病灶 | 例子 |
|---|---|
| 时间失效 | 三周前说"我下周要搬家"，今天问"他住哪"→ 召回那条，被当成现状 |
| 玩笑当真 | 「我打算把公司买了」是玩笑，语义上和正经陈述一样近 |
| 前后颠倒 | 同一件事的"起因"和"结果"在向量空间里几乎同距，来龙去脉被拍平 |

替代方案是**结构化字段 + 分层卡片**：

```
trace      原始的逐字对话（不参与检索，只能经卡片指针翻回去）
card       检索单元：一条自足的事 + event_at + status + keywords + attention
card_link  卡片之间**声明式**的因果（串线的第一依据）
thread     来龙去脉：同一主题的几张卡按时间串起来，附一句"演变"
```

检索走六路（关键词 / 时间窗 / 未了之事 / 种子卡片 / 情绪同频 / 反刍），打分后按**时间覆盖**挑选，最后对命中的卡片做**线程展开 + 因果展开**，把"前后变化"连同那条线的演变一起带进提示词。

> **v3 移除了"人物通道"**：单用户部署下 `cardsByPerson(primary, 15)` 每轮都返回同一批最近的卡，等于给全库白送 0.06 分，还把候选池撑大、把反刍通道饿死。
> **v4 没有把它加回来**——人物维度现在承担的是"这个人是谁 / 我知道他什么"，不是排序。
> 多个人同时在场之前，它不该回到打分公式里。

## 接真实模型

**不用改任何配置**：key 在下面任一个位置，启动时自动切到真实模型（默认 DeepSeek）。

| 放法 | 例子 |
|---|---|
| 主目录一个文件（推荐） | `~/.deepseek_api_key`（文件里只写 `sk-xxxx`） |
| 环境变量 | `set DH_API_KEY=sk-...` |
| 项目里 `.env` | `DH_API_KEY=sk-...`（已 gitignore） |
| 显式指定路径 | `set DH_API_KEY_FILE=D:\keys\ds.txt` |

查找顺序：环境变量 → `.env` → `DH_API_KEY_FILE` → `~/.deepseek_api_key` → `~/.deepseek.key`
→ `~/deepseek_api_key.txt` → `~/api-key.txt` → `~/.api-key` → 项目根 `api-key.txt` → `src/api-key.txt`（会被标红）。
启动横幅会显示 key 从哪来（只显示 `sk-…abcd` 尾号）。

换端点/模型建一个 `.env`：

```bash
DH_PROVIDER=openai                       # 或 anthropic
DH_BASE_URL=https://api.deepseek.com/v1  # 任何 OpenAI 兼容端点
DH_EXPRESS_MODEL=deepseek-chat           # 表达层：用最好的
DH_APPRAISE_MODEL=deepseek-chat          # 编码层：用便宜快的
```

> **一条硬建议**：两个模型用**不同厂商**。同一个模型既写记忆又表演、还当 judge，
> 会系统性地把自己写得更讨喜、也更容易给自己打高分。开发期只有一把 key 时先这样。

## 它内部发生了什么

```
你说一句话
  → 认人                  他这句话说明了自己是谁吗（同步、纯规则）
  → reader.readUserTurn() 纯规则读这句话在干什么（关心/问感受/夸/催），0 成本
  → 动机引擎取当前的动机卡（每 30 秒算一拍，纯计算，0 成本）
      被动路径从五种接法里选一种；主动路径过三道闸门（张力/迟滞/全局间隔）
  → 召回：关键词/时间窗/未了之事/种子/情绪同频/反刍 →
      打分 → 相对截断 → 时间覆盖选择 → 线程展开 + 因果展开
  → 提示词组装：卡片骨架给「时间 · 状态 · 一句话 · 60 字摘录」
      + ◎ 我注意到的 + ○ 我当时没懂的 + ≈ 这条线的演变
  → 强模型说话
  → express/verify 校验句数/禁语/复述 → 不合格带着清单重说一次
  → 后台异步：主观编码 → 写卡片（判重/合并）+ 写因果边 + 记原始记录区间
```

关键的四条纪律（代码里真的执行了）：

1. **LLM 不决定"想干什么"**，只决定"怎么说"。动机卡带 `must_not` 和 `max_sentences`，
   后者由 `verify.ts` 强制，前者里能机器判定的部分（禁语、复述）也被强制。
2. **卡片必须回答五个问题**：什么时候、是什么、现在还成不成立、以后怎么搜到、**我有多确定**。
3. **唯一写入者**：只有 `memory/appraise.ts` + `memory/cards.ts` 能写卡片。
4. **状态有两个写入者**：编码器（判断）+ 时钟（`refreshStatuses`）。前者管"改口了"，
   后者管"时间过去了"——后者是 v2 最原始的病灶唯一的机制解。

## 两个角色：档案库 与 管理员

**档案库** —— `store/` + `memory/retrieve.ts`

- 四层：`trace`（逐字）→ `card`（检索单元）→ `card_link`（声明式因果）→ `thread`（来龙去脉）
- 写入有规矩：唯一写入者，每张卡必须带**时间 / 状态 / 关键词 / 确定度**
- 检索有索引：六路并行；`status` / `kind` / `confidence` 都是乘性惩罚

**管理员** —— `memory/consolidate.ts` + `memory/status.ts`

- 只在需要时干活：合并重复、串线、写演变、归档死账、按时间过期、重写印象、清日志
- 三条自律：
  - 没有新卡片的线**不重写**演变（`thread.summarized_at`）
  - 自己的账本也要清（召回 90 天 / 调用 30 天）
  - 结构换代先备份旧库；**纯增量加列不升版本**，用 `ensureColumn()` 就地补
- 触发方式：`/sleep`，或退出前

## 对话记录的格式约定

全系统只有一处渲染（[dialogue.ts](src/shared/dialogue.ts)）：

```
今天上线又崩了，我盯到凌晨。          ← 他说的，没有标注
我：凌晨几点。                        ← 我说的
三点多。
```

**他的话不加任何前缀**（不要「他：」，更不要「用户：」）。理由是这份记录是**她的**：
她的话有主人，他的话只是"被我说出来的话"。第三人称标签会让模型开始模仿那种标签体，
而且会把"对话记录"读成"两个人的档案"，那是另一套语气。

这条约定有测试锁着（[dialogue.test.ts](tests/dialogue.test.ts)），四处渲染口
（编码器看的历史 / 表达层看的近几轮 / 翻出来的原话 / `/expand`）都必须走同一个函数。

## 改人设

人设文件，改完 `/reseed`（或重启）：

| 文件 | 是什么 | 进哪里 |
|---|---|---|
| `persona/identity.md` | 人格内核（特质+触发+反方向表现） | system 提示词（跨轮不变，命中缓存） |
| `persona/voice.json` | 说话契约（正例/反例/硬禁用） | system 提示词 + **`verify.ts` 会逐字扫 `banned_phrases`** |
| `persona/seed-self.md` | 我**现在**怎么认识自己 | user 慢变区，会被巩固任务改写 |
| `persona/self.json` | 「我」的称呼（**可选**，仓库里没带） | 记下他叫我什么（**不**用来挡误会） |

前三个是必需的；`self.json` 缺了只意味着"她还没给自己起名字"（仓库带的白模就是这样）。

写人设的三条经验（都是踩出来的）：

1. **一个特质要写三段**：倾向 → 触发条件 → **反方向的表现**。
   只写"她害怕攒回忆"会得到一个失忆系角色；补上"但她记性其实很好，而且为此不高兴"才像人。
2. **每条都要能指到一个机制。** 指不到的先别写。
   `identity.md` 现在的六节各自对应一条意图、一个字段或一道闸门（见 docs §19 的对照表）。
   写进去却没有任何东西承接的条目，不会消失，只会稀释其他每一条 —— 那是形式主义。
3. **绝对化用词要软。** 「只有一招」改成「通常只有一个办法」。写死"从不 X"等于剥夺她出错的空间；
   而我们的分寸是：机制要准，内容可以错。

> **明确不做（等之后安排）**：ERROR 句式（这个角色的底层逻辑，要作为机制做，不能当口癖）、
> 与外物互动的特质（照料活的东西之类）、生气／冲突（缺 `push_back` 意图，见 docs §19.4）。
> 曾经有过第五个文件 `scenes.json`（关键袒露的闸门），**v4.2 删掉了** —— 理由见 docs §20。
> 这三样现在连一个字都不在提示词里 —— 写了也执行不到，不如空着。

## 评测

```bash
npm run test                          # 106 个单元/集成测试（含真机踩出来的回归）
npm run eval                          # 19 项确定性检查，不调模型，几秒
npm run eval -- --live                # 再用真模型跑 10 轮，打印对话与合规表
npm run eval -- --live --judge        # 再加一个 judge 打三档分
npm run typecheck                     # tsc --noEmit（strict 是真的会检查的）
```

`npm run eval` 分两层，这个区分很重要：
- **第一层不需要模型**：时间窗、状态压制、去重、串线、反刍、审计规则——全是确定性的，
  跑一万遍结果一样。改检索参数时先跑这一层。
- **第二层才是真机**：验证"像不像人"。judge 给三档分（动机忠实度 / 记忆忠实度 / 人味），
  设计目标是幻觉率 < 2%。

测试断言的是**机制**，不是**内容**：名字会不会被绑上、绑错了能不能改、问身份的额度用完没有。
"认出来的名字对不对"不写进单测硬编码——那是内容，由 `--live` 去观察。
单测一旦开始规定"这里应该认出开发者"，项目就开始向正确性倾斜了。

真机那层的价值已经被验证过两次：
第一次 judge 报记忆忠实度 6.0，原因是她对着不存在的记忆说"我记得有这回事"——补了一条硬规则后升到 9.0。
第一次八轮对话**全都是 `reply`**，原因是回应型意图的门槛被设成了 0.45（需求从 0.18 涨到 0.45 要几个小时）——压到 0.15 后 `refuse_care` 正常触发。

> **没有这个评测集，你会在第 3 周开始凭感觉改提示词。**

## 已知边界（诚实清单）

- **`kindFactor` 压不过关键词名次**。玩笑卡的 0.75 折扣约等于 0.12 分，而 bm25 名次差能到 0.18。
  所以真正防止"玩笑被当成事实"的不是分数，是 `kind`/`status` 标签进提示词 + 表达层纪律。
  评测里那条断言因此改成"同一段文字下 joke 分值低于 event"——只测机制真的承诺过的那部分。
- **`rankScore` 没有并列处理**。两张**内容完全相同**的卡片会拿到 1.0 和 0.5 两个名次分。
- **`must_not` 里的语义禁忌没有执行**。"不许承认自己在勉强"这种只能靠模型自觉。
- **单用户**。人物通道已移除，但 v4 起 `person` 是真正的档案了：
  可以有多个人（提到「老王」就给他建一张），只是**同时只有一个在说话**。
- **认人靠规则，不靠声纹**。`ask_identity` 的前提是"我看不见你"，
  所以每次苏醒都要问一遍。真要做"自动认出是谁"，`awakening.identity_known`
  这一列已经留好了，把它写成 1 就不会问。
- **同义改写只靠巩固兜**。没有向量，关键词仍是 bigram+单字；换说法的重复要等 `/sleep` 的 LLM 判定。
- **judge 是同厂商自评**。开发期只有一把 key 时只能这样，分数要打个折扣看。
- **衰减有下限**：`strength` 不会低于 `0.15 × salience`，所以高 salience 的卡片永远死不掉，
  只会停在低分区。这是有意的（重要的事只该变模糊），代价是活集合只增不减，
  一年后需要一层显式归档。
- **关系只涨不跌**。`closeness` 每轮 +0.004，`warmth` / `trust` 从未被写过。
  冲突与修复还没做——那是下一个大块。

## 现在还没有的

- **图像形象 / 语音** —— `ExpressOutput` 里 `gaze` / `pause_before_ms` / `emotion.intensity`
  三个字段已经出现但还没有消费者，留给以后接形象。
- **桌面壳 / 记忆浏览器** —— `brain` 不依赖任何 UI，`/why` `/audit` `/recall` 是它的替代品。
- **迁移器** —— 破坏性结构变更时旧库整份备份成 `.bak`，然后按新结构重建。
  纯增量（加列/加表）就地生效，**不需要重建**。
- **冲突与修复** —— 关系维度只会上升，需要负向事件源和修复对话。
- **人物档案的长期演进** —— 档案现在只会往里加（别名、traits），
  不会"改主意"：如果他对自己的描述前后矛盾，两张卡会并存，档案不会自己发现矛盾。
- **多人同时在场** —— 现在的模型是"一次一个谈话对象"。两个人在同一个房间说话，
  `speaker` 会来回跳，需要真正的说话人分离。
